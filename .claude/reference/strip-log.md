# Strip log

> What Ballast removed or switched off from Sure, and how each area resolves on an upstream merge. Upstream edits to a removed path → modify/delete conflict → `git rm <path>` keeps it gone. Switched-off areas stay in the tree and merge normally.

| Area | How | Paths / switch | On upstream merge |
|---|---|---|---|
| Release, mobile, chart, desktop, LLM-eval, sync and docs workflows; Dependabot; issue/discussion templates; Copilot instructions | Deleted | `.github/workflows/{publish,mobile-*,flutter-build,ios-testflight,google-play-upload,desktop-release,chart-*,helm-publish,llm-evals,sync-maybe-sure,update-docs}.yml`, `.github/dependabot.yml`, `.github/{ISSUE_TEMPLATE,DISCUSSION_TEMPLATE}/`, `.github/copilot-instructions.md` | `git rm` any re-added or modified copy; new upstream workflows → review before keeping |
| Flutter mobile app, macOS desktop app, Helm chart, other agents' config | Deleted | `mobile/`, `desktop/`, `charts/`, `.cursor/`, `.gemini/`, `.junie/` | `git rm -r` |
| Pipelock workflow (renders `charts/sure`, so it can't run without the chart) | Deleted; `pr.yml` loses its `charts/**` paths-ignore | `.github/workflows/pipelock.yml` | `git rm`; keep our `pr.yml` |
| Telemetry: Sentry, PostHog (incl. Sure's bundled self-hosted usage/feedback project), Langfuse, Skylight, Logtail | Config-off: `config/initializers/0_ballast_no_telemetry.rb` loads right after `00_ssl.rb`, before the telemetry initializers, deletes their env keys and forces `POSTHOG_FEEDBACK_ENABLED=false`. Logtail: `config/environments/production.rb` (loads before initializers) now always builds the STDOUT logger; the `logtail-rails` gem, `config/initializers/logtail.rb` and system-health checks stay. Gems and call sites stay (Sentry is called from ~50 files). `SKYLIGHT_ENABLED` is still read by `Gemfile` and `config/application.rb` before the initializer; harmless, it only moves the gem to the development group (`require: false`) | `SENTRY_DSN`, `POSTHOG_*`, `LANGFUSE_*`, `SKYLIGHT_*`, `LOGTAIL_API_KEY`, `LOGTAIL_INGESTING_HOST` ignored | Merges normally, except `config/environments/production.rb`: keep our STDOUT-only `base_logger` if upstream edits that block. Grep new initializers, environment files and env vars for telemetry or log shipping and add them to the list |
| Cloud file storage (Amazon S3, Cloudflare R2, generic S3, Google Cloud Storage) | Deleted: gems `aws-sdk-s3` and `google-cloud-storage` (and their lockfile dependencies), the four cloud services in `config/storage.yml`, the cloud branches of the system-health storage check, their locale keys and tests. `config/environments/{production,development}.rb` hard-code `config.active_storage.service = :local`; `ACTIVE_STORAGE_SERVICE` is no longer read. Active Storage itself and its tables stay | `Gemfile`, `Gemfile.lock`, `config/storage.yml` (only `local`, `test`), `config/environments/{production,development}.rb`, `app/models/configuration_health.rb` (`STORAGE_BACKENDS`, `storage`), `config/locales/views/admin/system_health/{en,de,fr}.yml`, `test/models/configuration_health_test.rb`, `test/controllers/admin/system_health_controller_test.rb` | Shared files carry our edits: keep our side in `Gemfile` (no cloud gems; regenerate `Gemfile.lock` with `bundle install`), `config/storage.yml`, the `active_storage.service` line in both environment files, and the `storage` check. Upstream locale or test additions for cloud backends → drop them |

Kept workflows: `pr.yml` → `ci.yml` (tests, lint, Brakeman) and our `secrets-guard.yml`. Kept `.sure-version`: read by `config/initializers/version.rb`. Mobile/desktop SSO routes and API stay until the SSO step.
